# Port batch 2 — ASD + cross-reference: known-answer expectations

**Committed BEFORE the batch was implemented or run, and never edited
afterwards.** A wrong expectation is corrected only by a dated note in a
NEW file.

Scope: the 11 ours-only functions in `asd` (6) and `cross_reference` (5)
from the old repo (`Biolab/alloagent/tool/`).

## Data

| what | where | size |
|---|---|---|
| ASD XF (XML, per-protein allosteric data) | `/biolab_data/asd/ASD_Release_202306_XF` | 2,419 files |
| ASD 2D (`.mol`) | `/biolab_data/asd/ASD_Release_202306_2D` | 99,961 files |

The protein -> XML mapping is committed as `biomni/tool/_asd_index.tsv`
(2,412 proteins, generated by `scripts/_gen_asd_index.py` from the real
XF directory) instead of the old repo's 75 KB Python dict.

## Framework adaptation

- the standard contract dict; no stdout; errors as `success=False`;
- `parse_asd_xf` / `load_asd_2d` / `load_asd_3d` return the dict
  directly instead of a bare dict of dicts;
- `cross_reference_ligands` returns a **dict**, not the JSON *string* the
  old tool returned (the per-run recorder is JSON; the old string form
  is what an LLM prompt used to receive);
- `retrieve_and_filter_large_dataset` always returns the dict form; the
  old `return_format="dataframe"` branch is gone because a DataFrame
  cannot be recorded.

## Two real defects in the old code, fixed by this port

1. **`cross_reference` called two functions that do not exist.**
   `alloagent/tool/cross_reference.py` calls
   `asd.get_asd_ap_data(...)` and `asd.get_asd_dr_data(...)`, but the
   old `alloagent/tool/asd.py` defines neither. Both calls sat inside
   `try/except Exception: pass`, so the ASD AP and ASD DR branches were
   **always empty** and the tool silently returned only BioLiP and
   ChEMBL/PubChem data. The port implements both readers (as private
   helpers, so the exposed tool list does not grow beyond the port
   scope) and the AP branch now returns real rows.

2. **The DR dataset cannot be joined to a UniProt accession.**
   `ASD_Release_201909_DR.csv` keys drugs by `target_id`, whose values
   are ASD protein ids such as `ASD01140000_3`. Those ids are **disjoint**
   from the XF index's 2,018 ASD prefixes: joining all 538 DR rows
   against the whole index gives **0** matches. The port therefore
   exposes DR by its own keys (drug serial, ASD target id, drug name)
   and does not pretend a UniProt join exists.

## Non-goals

- Nothing here predicts an allosteric site. The XF file records sites
  that have already been curated; the AP file records computed pockets.
- The `use_llm` summary of `cross_reference_ligands` is best-effort and
  may return the documented "not available" string when no model is
  configured. It is never asserted in the known-answer tests.
